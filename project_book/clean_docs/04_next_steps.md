# Next Steps

## Agenda For The Next Fixer

- Confirm the copied starter is inside the intended project root.
- Ask the Architect which project should use this Project Book first.
- Use `project_book/templates/project_initialization.md` for the first project interview.
- Fill the clean docs with project-specific context.
- Create one small Netrunner session with clear validation, explicit execution path, execution rationale, and Architect launch command.
- Keep the first session focused on proving the workflow, not building a large system.

## Recommended First Session Types

- Project intake: turn a rough idea into overview, current state, target direction, and first success metric.
- Context cleanup: organize scattered notes into `clean_docs`.
- Prototype slice: build the smallest working piece that proves user value.
- Research slice: answer one concrete unknown with sources and implications.
- Review slice: inspect an existing artifact and decide what should change next.

## First Session Rule

The first real Netrunner session should be small enough to finish, review, and learn from in one pass.

After a Netrunner finishes a session, review it before using its output as the foundation for the next dependent session.

## Stop Rule

Do not widen into platform design, broad refactors, or multi-agent swarms until one small project loop has been finished and reviewed.
